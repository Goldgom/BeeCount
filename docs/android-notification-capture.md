# 安卓日常支出：通知采集 + 账单对账补漏

## 推荐方式与边界

使用 **通知自动采集 → 本地待确认 → 人工核对入账**，并定期导入微信／支付宝账单补漏。通知不能代替账单，不能承诺 100% 获取：

- 微信、支付宝、银行必须实际发出包含明确交易金额的通知；应用内的支付成功页不等于系统通知。
- 来源应用关闭交易通知、通知隐藏金额、Android 15+ 敏感通知保护、锁屏、工作资料隔离、厂商后台策略等都可能导致无法采集。
- 用户强制停止蜜蜂记账后，需重新打开。系统重新连接时仅尝试恢复**仍在通知栏显示**的通知，不读取已撤销的历史通知或账户历史流水。
- 相同交易可能同时有银行和支付平台通知。本实现不跨来源武断合并，避免误删真实交易；确认前检查近 300 笔记录，遇到同金额、通知时间前后 10 分钟内支出会明确警告。
- 短时间相同来源／原文通知和相同事件指纹会去重。不同内容的通知更新仍可能成为单独候选，必须核对。
- 所有候选都需要用户确认。金额不明确、转账／充值／提现／还款／退款／收入／失败／优惠等通知不会提供一键入账，防止把资金流动或营销金额当消费。

## 用户设置

1. 打开 **我的 → 自动化 → 支出通知采集**；现有截图自动记账设置中也有“支出通知采集（无需 AI）”入口。
2. 阅读本地采集说明，打开“启用本地采集”（默认关闭）。
3. 点击“手动授予／撤销通知使用权”，在 Android 系统设置中主动授权对应安装版本。测试版和正式版是不同应用，要授权实际使用的版本。此权限不同于“允许蜜蜂记账发送通知”，不需要授予照片、麦克风或无障碍权限。
4. 返回页面，点击刷新，确认“系统授权：已授权；监听连接：已连接”。未连接可“请求重新连接”；仍未连接可在系统撤销后重新授予，并检查设备后台／自启动／电池限制。
5. 点击“管理微信／支付宝／银行来源”。默认仅允许微信、支付宝和部分常见银行正式包名。银行地区版、测试版等包名不同，需要核实实际 Android 包名后手动加入，每行一个，不要加入无关聊天应用。
6. 在来源应用中开启消费交易通知。发生真实消费后检查最近采集时间和“待确认”。原文可展开查看；核对实际消费、来源、时间、金额及重复提醒。
7. 选择人民币个人账本后“核对并确认支出”。金额按明确人民币消费提取，最终确认对话框显示当前账本及原文。保存未分类、无账户支出，避免猜测账户或改变银行卡余额；随后可在普通交易编辑中完善分类／账户。外币和共享账本要求手动记账，避免错误折算或错误共享。
8. 每周／每月通过“微信／支付宝账单导入补漏与对账”进入现有导入流程；核对导入预览中的重复记录，不要把通知自动采集当作完整账单。

## 隐私与恢复

- Android 原生 NotificationListenerService 在 Flutter 未启动时也能接收系统回调，写入应用私有 `noBackupFilesDir/billing_notifications.json`，使用 AtomicFile 原子保存；不依赖 Dart 后台常驻。
- 原文、来源包名、通知时间、采集时间及 SHA-256 指纹只在设备采集队列中保存，排除 Android 自动备份；解析不调用 AI、网络或日志。
- 确认或忽略后立即移除原文，仅保留指纹、来源、时间和处理状态，用于去重。账本只保存来源包名及指纹摘要，不包含原文；若用户启用账本同步，这条已确认交易和简短来源备注会按正常同步规则同步。
- 入账使用稳定的事件 syncId。数据库写入成功但队列标记失败时，重试先查该 syncId，不会再次插入同一事件。
- 队列上限 5000 条（含处理历史），达到上限停止新增并在诊断中提示，**不会静默淘汰待确认原文**。清空采集数据需二次确认；不删除已确认账单，但清空指纹后仍在通知栏的旧通知可能再次采集。
- Android 系统授权代表 OS 允许监听所有通知，本应用在回调中只保存允许来源且包含交易关键词的通知。任何来源文字都不可信，用户仍须核对真实性。
- 停用开关停止保存新通知但不撤销 OS 授权。要彻底撤销监听权，在系统通知使用权设置关闭。卸载清除本地采集队列。

## 真机验收（必须由用户主动授权）

开发环境没有连接 Android 设备，以下不能用单元测试代替：

1. 未授权、已授权未启用、启用后撤权三种状态下应无新原文保存；UI 状态刷新准确。
2. 授权启用后分别用微信／支付宝／实际安装银行收到一条包含明确人民币消费金额的系统通知，核对来源、通知原文、通知时间与采集时间。
3. 不保持 Flutter 前台，收到通知后再打开页面，候选仍在；普通杀后台／系统重连后重复通知不重复入账。
4. 通知含“消费人民币32.50元，余额10000元”只提取32.50；转账、充值、退款、验证码等不提供一键入账。内容被系统隐藏时显示需核对或不采集，不能伪造金额。
5. 同消费同时收到银行和支付平台通知，确认第一条后第二条提示同额近时记录；核对后忽略重复，原文被移除。
6. 确认取消不入账；确认成功真实账本新增一次；清空队列不删除账本；没有支付、划转、读银行账户或无障碍操作。
7. 再导入官方导出的账单核对缺漏，检查来源应用根本没发通知的消费不会被错误声称已捕获。

- Android `./gradlew :app:compileDevDebugKotlin -x :app:compileFlutterBuildDevDebug --console=plain`：成功，包含监听服务、清单与 MainActivity 原生桥；不等同于完整 APK 或真机端到端验证。
